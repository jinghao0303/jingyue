## 二、数据表结构详解

### 2.1 省份表：`provinces`

**表名**：`provinces`  
**数据库**：`Infectious_disease_data`  
**用途**：存储省份基础信息，作为城市表的上级关联表  
**创建SQL**：`backend/database/region_tables.sql`

| 字段名 | 类型 | 是否必需 | 说明 | 模型用途 |
|--------|------|---------|------|----------|
| `id` | INT | ✅ | 省份ID（主键） | 关联键，cities表的外键 |
| `province_code` | VARCHAR(10) | ✅ | 省份代码（唯一，如：44） | 省份标识码 |
| `province_name` | VARCHAR(50) | ✅ | 省份名称（唯一，如：广东省） | 省份名称显示 |
| `status` | TINYINT | ✅ | 状态（1-启用，0-禁用） | 数据有效性控制 |
| `created_at` | DATETIME | ✅ | 创建时间 | 记录时间 |
| `updated_at` | DATETIME | ✅ | 更新时间 | 记录时间 |

**索引信息**：
- 主键：`id`
- 唯一索引：`province_code`, `province_name`
- 普通索引：`idx_province_code`, `idx_province_name`

**关联关系**：
- `cities.province_id` → `provinces.id` (1:N)

**模型用途**：
- 主要用于数据组织和管理
- 通过 `cities` 表间接关联到模型数据

### 2.2 城市表：`cities`

**表名**：`cities`  
**数据库**：`Infectious_disease_data`  
**用途**：存储城市基础信息，所有模型都通过city_id关联此表  
**创建SQL**：`backend/database/region_tables.sql`

| 字段名 | 类型 | 是否必需 | 说明 | 模型用途 |
|--------|------|---------|------|----------|
| `id` | INT | ✅ | 城市ID（主键） | **所有模型必需**：关联键，flu_daily_cases等表的外键 |
| `city_code` | VARCHAR(10) | ✅ | 城市代码（唯一，如：4418） | 城市标识码 |
| `city_name` | VARCHAR(50) | ✅ | 城市名称（如：清远市） | **所有模型必需**：查询数据时的标识 |
| `province_id` | INT | ✅ | 所属省份ID | 关联provinces表 |
| `latitude` | DECIMAL(10,6) | 可选 | 纬度 | 地理信息，可用于地图展示 |
| `longitude` | DECIMAL(10,6) | 可选 | 经度 | 地理信息，可用于地图展示 |
| `status` | TINYINT | ✅ | 状态（1-启用，0-禁用） | 数据有效性控制 |
| `created_at` | DATETIME | ✅ | 创建时间 | 记录时间 |
| `updated_at` | DATETIME | ✅ | 更新时间 | 记录时间 |

**索引信息**：
- 主键：`id`
- 唯一索引：`city_code`
- 普通索引：`idx_city_name`, `idx_province_id`
- 外键：`province_id` → `provinces.id`

**关联关系**：
- `cities.province_id` → `provinces.id` (N:1)
- `flu_daily_cases.city_id` → `cities.id` (N:1)
- `city_population.city_id` → `cities.id` (1:1)
- `flu_seir_predictions.city_id` → `cities.id` (N:1)
- `flu_lstm_models.city_id` → `cities.id` (N:1)
- `districts.city_id` → `cities.id` (N:1)

**模型用途**：
- **所有模型必需**：通过 `city_id` 筛选特定城市的数据
- 通过 `city_name` 进行城市名称查询

### 2.4 城市人口配置表：`city_population`

**表名**：`city_population`  
**数据库**：`Infectious_disease_data`  
**用途**：存储城市人口数据，用于SEIR模型计算总人口数  
**创建SQL**：`backend/database/region_tables.sql`

| 字段名 | 类型 | 是否必需 | 说明 | 模型用途 |
|--------|------|---------|------|----------|
| `id` | INT | ✅ | 主键ID | 数据库索引 |
| `city_id` | INT | ✅ | 城市ID（唯一，关联cities表） | **SEIR模型必需**：关联城市 |
| `total_population` | INT | ✅ | 总人口数（默认5000000） | **SEIR模型必需**：用于计算感染率、风险等级 |
| `population_year` | INT | 可选 | 人口数据年份 | 数据时效性追踪 |
| `data_source` | VARCHAR(100) | 可选 | 数据来源（如：统计年鉴） | 数据质量追踪 |
| `status` | TINYINT | ✅ | 状态（1-启用，0-禁用） | 数据有效性控制 |
| `created_at` | DATETIME | ✅ | 创建时间 | 记录时间 |
| `updated_at` | DATETIME | ✅ | 更新时间 | 记录时间 |

**索引信息**：
- 主键：`id`
- 唯一索引：`city_id`（一个城市只有一条人口记录）
- 普通索引：`idx_city_id`
- 外键：`city_id` → `cities.id`

**关联关系**：
- `city_population.city_id` → `cities.id` (1:1)

**模型用途**：
- **SEIR模型必需**：通过 `city_id` 关联获取 `total_population`
- 用于计算易感者数量 S = total_population - I - E - R
- 用于计算风险等级（峰值感染数 / 总人口数）

**查询示例**：
```sql
-- 通过城市名称获取总人口数
SELECT cp.total_population
FROM city_population cp
INNER JOIN cities c ON cp.city_id = c.id
WHERE c.city_name = '清远市';
```

## 三、城市关联表完整关系说明

### 3.1 表关联关系图

```

    ↓              │
city_population    │
(城市人口表)        │

```

### 3.2 城市数据获取完整流程

**通过城市名称获取所有相关数据：**

1. **查询城市基本信息**：
   ```sql
   SELECT c.id, c.city_name, c.city_code, c.latitude, c.longitude,
          p.province_name, p.province_code
   FROM cities c
   INNER JOIN provinces p ON c.province_id = p.id
   WHERE c.city_name = '清远市';
   ```

2. **查询城市人口信息**：
   ```sql
   SELECT cp.total_population, cp.population_year, cp.data_source
   FROM city_population cp
   INNER JOIN cities c ON cp.city_id = c.id
   WHERE c.city_name = '清远市';
   ```

3. **查询城市历史病例数据**：
   ```sql
   SELECT fdc.date, fdc.active, fdc.confirmed, fdc.recovered,
          fdc.deaths, fdc.new_cases
   FROM flu_daily_cases fdc
   INNER JOIN cities c ON fdc.city_id = c.id
   WHERE c.city_name = '清远市'
     AND fdc.date >= DATE_SUB(CURDATE(), INTERVAL 60 DAY)
   ORDER BY fdc.date ASC;
   ```

## 四、各模型使用的数据字段

### 4.1 SEIR 动力学模型

**数据需求：**

| 字段 | 用途 | 优先级 | 说明 |
|------|------|--------|------|
| `active` | 初始感染数 | ⭐⭐⭐ 最高 | 作为 `I(0)` 初始值 |
| `recovered` | 初始康复数 | ⭐⭐ 高 | 作为 `R(0)` 初始值（可选，默认0） |
| `total_population` | 总人口数 | ⭐⭐⭐ 最高 | 从cities表获取，用于计算S、E、I、R各状态 |
| `date` | 时间序列 | ⭐⭐⭐ 最高 | 用于确定预测的起始日期 |
| `city_id` | 数据筛选 | ⭐⭐⭐ 最高 | 筛选特定城市的数据 |

**涉及的数据表**：
- `cities` - 获取城市ID和名称（通过city_name查询）
- `city_population` - 获取总人口数（通过city_id关联）
- `flu_daily_cases` - 获取初始感染数和康复数（通过city_id关联）

**数据获取逻辑：**

1. **初始感染数（initial_infected）**：
   - 数据表：`flu_daily_cases`
   - 优先使用：`active` 字段
   - 备用方案：`confirmed - recovered`（如果active为空）
   - 最后方案：使用 `confirmed`（如果前两者都为空）

2. **初始康复数（initial_recovered）**：
   - 数据表：`flu_daily_cases`
   - 使用：`recovered` 字段（如果为空则默认为0）

3. **总人口数（total_population）**：
   - 数据表：`city_population`（通过 `cities.id` 关联）
   - 查询方式：
     ```sql
     SELECT cp.total_population
     FROM city_population cp
     INNER JOIN cities c ON cp.city_id = c.id
     WHERE c.city_name = ?;
     ```

**数据量要求：**
- 最少：1条记录（用于获取初始值）
- 推荐：3-7条历史记录（用于数据质量验证和趋势分析）

---

### 4.2 LSTM 深度学习模型

**数据需求：**

| 字段 | 用途 | 优先级 | 说明 |
|------|------|--------|------|
| `active` | **训练目标值** | ⭐⭐⭐ 最高 | **核心字段**：作为时间序列的y值 |
| `date` | 时间序列排序 | ⭐⭐⭐ 最高 | 用于按时间顺序排列数据 |
| `city_id` | 数据筛选 | ⭐⭐⭐ 最高 | 筛选特定城市的数据 |

**涉及的数据表**：
- `cities` - 获取城市ID和名称（通过city_name查询）
- `flu_daily_cases` - 获取历史数据序列（通过city_id关联）
- `flu_lstm_models` - 保存训练记录（通过city_id关联）

**数据获取逻辑：**

1. **训练数据序列**：
   - 数据表：`flu_daily_cases`
   - 查询SQL：`SELECT date, active, confirmed, recovered FROM flu_daily_cases WHERE city_id = ? AND date >= ? AND date <= ? ORDER BY date ASC`
   - 提取 `active` 字段作为训练序列
   - 如果 `active` 为空，使用 `confirmed - recovered` 计算
   - 如果仍为空，使用 `confirmed`（不推荐）

2. **数据预处理**：
   - 使用 MinMaxScaler 归一化到 [0, 1] 范围
   - 序列长度：14天（使用过去14天预测下1天）

**数据量要求：**
- **训练最少**：30天历史数据
- **训练推荐**：60-90天历史数据
- **预测最少**：14天历史数据（用于构建输入序列）
- **预测推荐**：30天以上历史数据

**数据质量要求：**
- 数据应该连续，避免大量缺失值
- 如果某天数据缺失，会跳过该记录（不填充0）

### 4.3 Prophet 时序预测模型

**数据需求：**

| 字段 | 用途 | 优先级 | 说明 |
|------|------|--------|------|
| `active` | **预测目标值** | ⭐⭐⭐ 最高 | **核心字段**：作为时间序列的y值 |
| `date` | 时间戳 | ⭐⭐⭐ 最高 | 转换为Prophet需要的ds格式 |
| `city_id` | 数据筛选 | ⭐⭐⭐ 最高 | 筛选特定城市的数据 |

**涉及的数据表**：
- `cities` - 获取城市ID和名称（通过city_name查询）
- `flu_daily_cases` - 获取历史数据序列（通过city_id关联）

**数据获取逻辑：**

1. **训练数据格式**：
   - 数据表：`flu_daily_cases`
   - 查询SQL：`SELECT date, active, confirmed, recovered FROM flu_daily_cases WHERE city_id = ? AND date >= ? AND date <= ? ORDER BY date ASC`
   - 提取 `active` 字段作为y值
   - 提取 `date` 字段转换为Prophet的ds格式（datetime类型）
   - 如果 `active` 为空，使用 `confirmed - recovered` 计算

2. **Prophet数据格式**：
   ```python
   DataFrame({
       'ds': [datetime对象],  # 日期
       'y': [float数值]       # 活跃病例数
   })
   ```

**数据量要求：**
- **最少**：30天历史数据
- **推荐**：90天以上历史数据（能更好地识别季节性模式）

**数据质量要求：**
- 数据应该连续
- Prophet会自动处理缺失值，但数据越完整越好

---

## 五、数据字段优先级和使用规则

### 3.1 活跃病例数（active）的获取优先级

所有模型都优先使用 `active` 字段，获取逻辑如下：

```
1. 优先使用：active 字段（如果存在且不为NULL）
   ↓
2. 备用方案：confirmed - recovered（如果两者都存在）
   ↓
3. 最后方案：confirmed 字段（如果前两者都不可用）
   ↓
4. 数据无效：跳过该条记录（不填充0，避免数据质量差）
```

### 3.2 数据查询示例

**LSTM模型训练数据查询（通过城市名称）：**
```sql
USE Infectious_disease_data;

-- 步骤1：通过城市名称获取city_id
SELECT id FROM cities WHERE city_name = '清远市';

-- 步骤2：通过city_id获取历史数据
SELECT date, active, confirmed, recovered
FROM flu_daily_cases
WHERE city_id = (
    SELECT id FROM cities WHERE city_name = '清远市'
)
  AND date >= DATE_SUB(CURDATE(), INTERVAL 60 DAY)
  AND date <= CURDATE()
ORDER BY date ASC;
```

**SEIR模型初始值查询（通过城市名称）：**
```sql
USE Infectious_disease_data;

-- 获取初始感染数和康复数
SELECT fdc.date, fdc.active, fdc.recovered
FROM flu_daily_cases fdc
INNER JOIN cities c ON fdc.city_id = c.id
WHERE c.city_name = '清远市'
  AND fdc.date = CURDATE()
ORDER BY fdc.date DESC
LIMIT 1;

-- 获取总人口数
SELECT cp.total_population
FROM city_population cp
INNER JOIN cities c ON cp.city_id = c.id
WHERE c.city_name = '清远市';
```

**Prophet模型数据查询（通过城市名称）：**
```sql
USE Infectious_disease_data;

SELECT fdc.date, fdc.active, fdc.confirmed, fdc.recovered
FROM flu_daily_cases fdc
INNER JOIN cities c ON fdc.city_id = c.id
WHERE c.city_name = '清远市'
  AND fdc.date >= DATE_SUB(CURDATE(), INTERVAL 90 DAY)
  AND fdc.date <= CURDATE()
ORDER BY fdc.date ASC;
```

**完整关联查询示例（获取城市所有相关信息）：**
```sql
USE Infectious_disease_data;

SELECT 
    c.id AS city_id,
    c.city_name,
    c.city_code,
    p.province_name,
    cp.total_population,
    fdc.date,
    fdc.active,
    fdc.confirmed,
    fdc.recovered
FROM cities c
INNER JOIN provinces p ON c.province_id = p.id
LEFT JOIN city_population cp ON c.id = cp.city_id
LEFT JOIN flu_daily_cases fdc ON c.id = fdc.city_id
WHERE c.city_name = '清远市'
  AND fdc.date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
ORDER BY fdc.date DESC;
```

## 六、数据质量要求

### 4.1 必需字段完整性

| 字段 | 完整性要求 | 说明 |
|------|-----------|------|
| `date` | 100% | 每条记录必须有日期 |
| `city_id` | 100% | 每条记录必须关联城市 |
| `active` | ≥80% | 至少80%的记录有active值（推荐） |

### 4.2 数据连续性

- **推荐**：数据应该连续，每天都有记录
- **可接受**：允许少量缺失（<10%），模型会自动处理
- **不推荐**：大量缺失（>20%）会影响模型准确性

### 4.3 数据准确性

- `active` 值应该 ≥ 0（负数会被处理为0）
- `confirmed` ≥ `recovered`（逻辑校验）
- `active` ≤ `confirmed`（逻辑校验）

## 九、数据获取API说明

### 7.1 获取历史数据序列

**用途**：LSTM和Prophet模型训练/预测

**数据字段**：
- `date` - 日期
- `active` - 活跃病例数（核心）

**查询逻辑**：
```python
# 优先使用active
if case.active is not None:
    return case.active
elif case.confirmed is not None and case.recovered is not None:
    return max(0, case.confirmed - case.recovered)
elif case.confirmed is not None:
    return case.confirmed
else:
    # 跳过该记录
    continue
```

### 7.2 获取初始状态

**用途**：SEIR模型初始值

**数据字段**：
- `active` - 初始感染数
- `recovered` - 初始康复数
- `total_population` - 总人口数（从cities表获取）
