# 模型数据字段说明文档

本文档详细说明系统中各个预测模型（SEIR、LSTM、Prophet）在训练和预测时需要用到的数据字段。

---

## 一、数据表结构

### 1.1 核心数据表：`flu_daily_cases`

这是存储每日流感病例数据的主表，所有模型都从这个表获取数据。

**表结构：**

| 字段名 | 类型 | 是否必需 | 说明 | 模型用途 |
|--------|------|---------|------|----------|
| `id` | BIGINT | ✅ | 主键ID | 数据库索引 |
| `date` | DATE | ✅ | 日期（格式：YYYY-MM-DD） | **所有模型必需**：用于时间序列排序 |
| `city_id` | INT | ✅ | 城市ID（外键关联cities表） | **所有模型必需**：筛选特定城市数据 |
| `active` | INT | ✅ **核心字段** | **当前活跃病例数** | **LSTM核心字段**：用于训练和预测<br>**SEIR初始值**：作为初始感染数<br>**Prophet目标值**：预测目标 |
| `confirmed` | INT | ✅ | 累计确诊数 | **备用字段**：当active为空时，用于计算活跃病例数 |
| `recovered` | INT | ⚠️ 推荐 | 累计康复数 | **备用字段**：与confirmed一起计算活跃病例数<br>**SEIR初始值**：作为初始康复者数 |
| `deaths` | INT | 可选 | 累计死亡数 | 扩展数据，可用于风险评估 |
| `new_cases` | INT | ⚠️ 推荐 | 当日新增病例数 | 扩展数据，可用于趋势分析 |
| `new_recovered` | INT | 可选 | 当日新增康复数 | 扩展数据 |
| `new_deaths` | INT | 可选 | 当日新增死亡数 | 扩展数据 |
| `hospitalized` | INT | 可选 | 当前住院人数 | 扩展数据 |
| `severe` | INT | 可选 | 当前重症病例数 | 扩展数据 |
| `data_source` | VARCHAR(100) | 可选 | 数据来源 | 数据质量追踪 |
| `remark` | TEXT | 可选 | 备注 | 数据说明 |

### 1.2 城市信息表：`cities`

存储城市基础信息，用于获取人口等参数。

| 字段名 | 类型 | 是否必需 | 说明 | 模型用途 |
|--------|------|---------|------|----------|
| `id` | INT | ✅ | 城市ID | 关联键 |
| `city_name` | VARCHAR(50) | ✅ | 城市名称 | **所有模型必需**：查询数据时的标识 |
| `total_population` | INT | ✅ | 总人口数 | **SEIR模型必需**：用于计算感染率、风险等级 |

## 二、各模型使用的数据字段

### 2.1 SEIR 动力学模型

**数据需求：**

| 字段 | 用途 | 优先级 | 说明 |
|------|------|--------|------|
| `active` | 初始感染数 | ⭐⭐⭐ 最高 | 作为 `I(0)` 初始值 |
| `recovered` | 初始康复数 | ⭐⭐ 高 | 作为 `R(0)` 初始值（可选，默认0） |
| `total_population` | 总人口数 | ⭐⭐⭐ 最高 | 从cities表获取，用于计算S、E、I、R各状态 |
| `date` | 时间序列 | ⭐⭐⭐ 最高 | 用于确定预测的起始日期 |
| `city_id` | 数据筛选 | ⭐⭐⭐ 最高 | 筛选特定城市的数据 |

**数据获取逻辑：**

1. **初始感染数（initial_infected）**：
   - 优先使用：`active` 字段
   - 备用方案：`confirmed - recovered`（如果active为空）
   - 最后方案：使用 `confirmed`（如果前两者都为空）

2. **初始康复数（initial_recovered）**：
   - 使用：`recovered` 字段（如果为空则默认为0）

3. **总人口数（total_population）**：
   - 从 `cities` 表的 `total_population` 字段获取

**数据量要求：**
- 最少：1条记录（用于获取初始值）
- 推荐：3-7条历史记录（用于数据质量验证和趋势分析）

---

### 2.2 LSTM 深度学习模型

**数据需求：**

| 字段 | 用途 | 优先级 | 说明 |
|------|------|--------|------|
| `active` | **训练目标值** | ⭐⭐⭐ 最高 | **核心字段**：作为时间序列的y值 |
| `date` | 时间序列排序 | ⭐⭐⭐ 最高 | 用于按时间顺序排列数据 |
| `city_id` | 数据筛选 | ⭐⭐⭐ 最高 | 筛选特定城市的数据 |

**数据获取逻辑：**

1. **训练数据序列**：
   - 从 `flu_daily_cases` 表按 `date` 升序查询
   - 提取 `active` 字段作为训练序列
   - 如果 `active` 为空，使用 `confirmed - recovered` 计算
   - 如果仍为空，使用 `confirmed`（不推荐）

2. **数据预处理**：
   - 使用 MinMaxScaler 归一化到 [0, 1] 范围
   - 序列长度：14天（使用过去14天预测下1天）

**数据量要求：**
- **训练最少**：30天历史数据
- **训练推荐**：60-90天历史数据
- **预测最少**：14天历史数据（用于构建输入序列）
- **预测推荐**：30天以上历史数据

**数据质量要求：**
- 数据应该连续，避免大量缺失值
- 如果某天数据缺失，会跳过该记录（不填充0）

---

### 2.3 Prophet 时序预测模型

**数据需求：**

| 字段 | 用途 | 优先级 | 说明 |
|------|------|--------|------|
| `active` | **预测目标值** | ⭐⭐⭐ 最高 | **核心字段**：作为时间序列的y值 |
| `date` | 时间戳 | ⭐⭐⭐ 最高 | 转换为Prophet需要的ds格式 |
| `city_id` | 数据筛选 | ⭐⭐⭐ 最高 | 筛选特定城市的数据 |

**数据获取逻辑：**

1. **训练数据格式**：
   - 从 `flu_daily_cases` 表按 `date` 升序查询
   - 提取 `active` 字段作为y值
   - 提取 `date` 字段转换为Prophet的ds格式（datetime类型）
   - 如果 `active` 为空，使用 `confirmed - recovered` 计算

2. **Prophet数据格式**：
   ```python
   DataFrame({
       'ds': [datetime对象],  # 日期
       'y': [float数值]       # 活跃病例数
   })
   ```

**数据量要求：**
- **最少**：30天历史数据
- **推荐**：90天以上历史数据（能更好地识别季节性模式）

**数据质量要求：**
- 数据应该连续
- Prophet会自动处理缺失值，但数据越完整越好

## 三、数据字段优先级和使用规则

### 3.1 活跃病例数（active）的获取优先级

所有模型都优先使用 `active` 字段，获取逻辑如下：

```
1. 优先使用：active 字段（如果存在且不为NULL）
   ↓
2. 备用方案：confirmed - recovered（如果两者都存在）
   ↓
3. 最后方案：confirmed 字段（如果前两者都不可用）
   ↓
4. 数据无效：跳过该条记录（不填充0，避免数据质量差）
```

### 3.2 数据查询示例

**LSTM模型训练数据查询：**
```sql
SELECT date, active, confirmed, recovered
FROM flu_daily_cases
WHERE city_id = ? 
  AND date >= DATE_SUB(CURDATE(), INTERVAL 60 DAY)
  AND date <= CURDATE()
ORDER BY date ASC;
```

**SEIR模型初始值查询：**
```sql
SELECT date, active, recovered
FROM flu_daily_cases
WHERE city_id = ?
  AND date = CURDATE()
ORDER BY date DESC
LIMIT 1;
```

## 四、数据质量要求

### 4.1 必需字段完整性

| 字段 | 完整性要求 | 说明 |
|------|-----------|------|
| `date` | 100% | 每条记录必须有日期 |
| `city_id` | 100% | 每条记录必须关联城市 |
| `active` | ≥80% | 至少80%的记录有active值（推荐） |

### 4.2 数据连续性

- **推荐**：数据应该连续，每天都有记录
- **可接受**：允许少量缺失（<10%），模型会自动处理
- **不推荐**：大量缺失（>20%）会影响模型准确性

### 4.3 数据准确性

- `active` 值应该 ≥ 0（负数会被处理为0）
- `confirmed` ≥ `recovered`（逻辑校验）
- `active` ≤ `confirmed`（逻辑校验）

## 六、数据字段使用总结

### 6.1 核心必需字段（所有模型）

1. ✅ **`date`** - 日期字段，用于时间序列排序
2. ✅ **`city_id`** - 城市ID，用于数据筛选
3. ✅ **`active`** - 活跃病例数，所有模型的核心数据字段

### 6.2 重要推荐字段

1. ⚠️ **`confirmed`** - 累计确诊数，作为active的备用数据源
2. ⚠️ **`recovered`** - 累计康复数，用于计算active和SEIR初始值
3. ⚠️ **`total_population`** - 总人口数（在cities表中），SEIR模型必需

### 6.3 扩展可选字段

1. `new_cases` - 新增病例数，可用于趋势分析
2. `deaths` - 死亡数，可用于风险评估
3. `hospitalized` - 住院人数，扩展数据
4. `severe` - 重症人数，扩展数据

## 七、数据获取API说明

### 7.1 获取历史数据序列

**用途**：LSTM和Prophet模型训练/预测

**数据字段**：
- `date` - 日期
- `active` - 活跃病例数（核心）

**查询逻辑**：
```python
# 优先使用active
if case.active is not None:
    return case.active
elif case.confirmed is not None and case.recovered is not None:
    return max(0, case.confirmed - case.recovered)
elif case.confirmed is not None:
    return case.confirmed
else:
    # 跳过该记录
    continue
```

### 7.2 获取初始状态

**用途**：SEIR模型初始值

**数据字段**：
- `active` - 初始感染数
- `recovered` - 初始康复数
- `total_population` - 总人口数（从cities表获取）

## 八、注意事项

1. **数据一致性**：确保 `active = confirmed - recovered` 的逻辑一致性
2. **数据时效性**：数据应该及时更新，推荐每天更新一次
3. **数据完整性**：尽量保证 `active` 字段的完整性，避免大量NULL值
4. **数据准确性**：确保数据来源可靠，避免错误数据影响模型预测
